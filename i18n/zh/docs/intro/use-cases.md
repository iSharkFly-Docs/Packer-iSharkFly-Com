# Packer 使用场景

本文介绍 Packer 的一些使用场景。这只是部分使用场景列表，旨在让你了解 Packer 如何改进你的流程。

## 持续交付

Packer 轻量、可移植且由命令行驱动。这使它成为放入持续交付流水线的完美工具。每当 Chef/Puppet 发生变更时，都可以使用 Packer 为多个平台生成新的机器镜像。

作为流水线的一部分，新创建的镜像可以被启动和测试，验证基础设施变更是否有效。如果测试通过，你可以确信镜像在部署时能正常工作。这为基础设施变更带来了新的稳定性和可测试性。

## 环境一致性

Packer 帮助保持开发、预发布和生产环境尽可能相似。请参阅以下外部文章了解更多关于环境一致性的信息：["X. 开发环境与生产环境等价"](http://www.12factor.net/dev-prod-parity)。

你可以使用 Packer 同时为多个平台生成镜像。因此，如果你在生产环境使用 AWS，在开发环境使用 VMware（可能配合 [Vagrant](https://www.vagrantup.com/)），你可以使用同一个模板同时生成 AMI 和 VMware 机器镜像。

将这与上面的持续交付用例结合起来，你就拥有了一个相当灵活的系统，从开发到生产的整个过程都能保持一致的工作环境。

## 设备和演示创建

因为 Packer 能够并行为多个平台创建一致的镜像，所以非常适合创建[软件设备](https://en.wikipedia.org/wiki/Software_appliance)和一次性产品演示。随着软件的变化，你可以自动创建预装了软件的设备。潜在用户可以通过将其部署到自己选择的环境来开始使用你的软件。
