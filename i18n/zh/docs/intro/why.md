# 为什么使用 Packer

本文介绍为什么应该使用 Packer 自动创建机器镜像，而不是传统的 _预制镜像_——预制镜像是预先配置好的数字镜像，包含必要的软件、设置和数据。

## 预制镜像

预制机器镜像有很多优势，但大多数人一直无法从中受益，因为镜像的创建和管理太过繁琐。要么没有现成的工具来自动创建机器镜像，要么这些工具的学习曲线太陡峭。结果是，在 Packer 出现之前，创建机器镜像威胁到运维团队的敏捷性，因此尽管有巨大的好处，人们也不愿意使用。

Packer 改变了这一切。Packer 可以自动创建任何类型的机器镜像。它拥抱现代配置管理理念，鼓励你使用 Chef 或 Puppet 等框架在 Packer 创建的镜像中安装和配置软件。

## 使用 Packer 的优势

**_超快的基础设施部署_**。Packer 镜像让你可以在几秒钟内启动完全配置好的机器，而不是几分钟或几小时。这不仅有利于生产环境，也有利于开发环境，因为开发虚拟机也可以在几秒钟内启动，而不用等待通常更长的配置时间。

**_多平台可移植性_**。因为 Packer 为多个平台创建相同的镜像，你可以在 AWS 上运行生产环境，在 OpenStack 等私有云上运行预发布/QA 环境，在 VMware 或 VirtualBox 等桌面虚拟化方案上进行开发。每个环境都运行相同的机器镜像，实现终极可移植性。

**_更高的稳定性_**。Packer 在构建镜像时安装和配置机器的所有软件。如果这些脚本中有 bug，会在早期就被发现，而不是在机器启动几分钟后。

**_更好的可测试性_**。机器镜像构建完成后，可以快速启动并进行冒烟测试，验证一切是否正常工作。如果测试通过，你可以确信从该镜像启动的任何其他机器都能正常运行。
