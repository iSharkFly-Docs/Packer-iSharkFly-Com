# Packer v1.11 发布说明

本页描述 Packer v1.11 中的更改。有关所有版本的信息，请参阅 [Packer 仓库](https://github.com/hashicorp/packer/releases)。

## 新功能

此版本包括以下更新。

### 可预测的插件加载

我们简化了 Packer 发现和加载插件的方式。Packer 不再加载安装在其插件目录之外的插件二进制文件。此外，Packer 现在只加载带有相应 SHA256SUM 文件的二进制文件。我们还更新了安装插件的命令，使大多数安装工作流程可以在不手动修改文件系统的情况下进行。我们还专注于提供清晰的说明，以便你了解流程以及如何解决潜在错误。

以前版本的 Packer 允许你在多个位置安装和加载插件，导致各种不一致。例如，在 HCL2 模板中配置 `required_plugins` 块会导致有限的插件可发现性。这不仅令人困惑，需要支持的替代路径数量也增加了维护负担。因为 Packer 在开始执行之前检查多个位置，许多命令都遭受不必要的性能问题。

有关更多信息，请参阅以下主题：

- [安装插件](/docs/plugins/install) 了解如何加载插件的详细信息。
- [升级到 v1.11](/docs/upgrade/v1_11) 了解这些更改可能如何影响你现有的工作流程。

## 弃用

以下功能、工作流程和组件已弃用，不再支持。

### 旧版单组件插件

Packer 不再支持单组件插件，例如遵循已弃用的 `packer-builder-<name>` 或 `packer-provisioner-<name>` 命名约定的旧版插件。Packer 仅支持多组件插件，例如 Packer 的 Docker 插件。

### 加载名为 `packer-plugin-<name>` 的插件二进制文件

Packer 不再加载遵循 `packer-plugin-<name>` 命名约定的插件二进制文件。Packer 仅加载使用预期的命名空间目录和 CHECKSUM 文件存储在 `PACKER_PLUGIN_PATH` 下的插件。

## 错误修复

修复了 Packer 发现插件的方式以确保正确的版本排序的问题。Packer 不再按字典顺序排列插件版本。相反，Packer 现在加载语义数字更大的版本。例如，版本 `1.0.9` 在字典顺序上大于 `1.0.10`，但 `1.0.10` 在语义上大于 `1.0.9`。此修复导致 Packer 加载 `1.0.10` 而不是 `1.0.9`。
