# Packer v1.12 发布说明

本页描述 Packer v1.12 中的更改。有关所有版本的信息，请参阅 [Packer 仓库](https://github.com/hashicorp/packer/releases)。

## 新功能

此版本包括以下更新。

### HCP Packer SBOM 支持

在 Packer 1.12 中，你可以将软件物料清单 (SBOM) 上传到 HCP Packer 并将其与制品版本关联。
SBOM 是一种标准化方式来导出有关系统的信息。
在 Packer 的情况下，你可能在制品的 SBOM 中找到的一般有用信息是已安装软件包的列表，以及关于构建系统的额外信息：操作系统、版本、内核、架构等。

虽然我们支持在构建过程中将 SBOM 上传到 HCP Packer，但我们不提供专门用于生成它们的配置器或工具。
相反，我们鼓励你使用第三方扫描器在你正在配置的 VM 上生成 SBOM，然后你可以使用 [`hcp-sbom` 配置器](/docs/provisioners/hcp-sbom) 在 Packer 构建完成时上传它。

### 数据源和本地变量求值顺序更改

旧版本的 Packer 使用基于阶段的方法，首先求值数据源，然后求值本地变量。
这使得数据源无法引用本地变量。

Packer 1.12 引入了用于求值数据源和本地变量的有向无环图 (DAG) 方法。
这放宽了这些组件之间的依赖顺序，现在你可以从两个上下文中引用它们。

此更改是完全转向使用 DAG 来求值 Packer 构建中所有内容的一步，以及这在未来版本中可能带来的其他改进。

### Packer-插件通信的序列化格式升级

一年多前，我们的一个依赖项 (`go-cty`) 放弃了对 `gob` 编码的支持。
这使得插件开发人员无法升级到更新版本的 HCL2 库，否则他们的插件将无法与 Packer 通信。
我们通过 fork `go-cty` 仓库并在每个 Packer 插件中引入替换指令来临时解决此问题。
虽然此修复是功能性的，但作为长期解决方案并不理想，我们一直在寻找更永久的修复。

现在，当 Packer 与插件通信时，它切换到使用 protobuf/msgpack 混合方法而不是依赖 `gob`。
我们现在以非破坏性方式引入此更改：所有当前支持的插件预计将在目前继续与 Packer 一起工作，切换到使用这种新的序列化方法对你来说将是透明的。

### 新的 HCL2 函数

作为 Packer 1.12 的一部分，我们引入了更多可在 HCL2 模板中使用的函数，以及一个 (`aws_secretsmanager_raw`) 可在旧版 JSON 和 HCL2 模板中使用。

* `anytrue`：检查集合是否包含至少一个 `true` 值。
* `alltrue`：检查集合是否只包含 `true` 值。
* `aws_secretsmanager_raw`：从 AWS Secrets Manager 获取原始密钥。与 `aws_secretsmanager` 不同，这适用于所有类型。
* `base64gzip`：gzip 压缩二进制 blob 并将其作为 base64 编码的 `string` 公开，以便在模板中的其他地方使用。
* `strcontains`：检查一个字符串是否包含另一个字符串。

### `HTTP` 数据源支持 `GET` 以外的方法

与 Packer 嵌入的 HTTP 数据源允许你通过 HTTP 从远程服务器检索数据。
以前版本的 Packer 仅支持 `GET` 来执行此操作。Packer 1.12 通过允许 `HEAD`、`GET`、`POST`、`PUT`、`DELETE`、`OPTIONS` 和 `PATCH` 来放宽这一限制。

## 错误修复

### 在 macOS 二进制文件中包含 LC_UUID

macOS 用户在升级其操作系统版本后，使用 Packer 时开始遇到与权限相关的问题。
此问题是由 macOS 网络使用策略的更新引起的，其中想要使用本地回环接口通过网络通信的二进制文件现在必须包含有效的 UUID。
从 Packer 1.12 开始，所有 macOS 二进制文件都包含有效的 LC_UUID，修复了此问题。

### HCL2 模板中更少的错误消息重复

如果模板在其顶级 HCL2 模板中有错误，Packer 会产生解析错误。
当你编写 Packer 模板时，这是预期的行为：该工具通过指出语法违规来帮助你，以便你可以修复它们。
然而，对于 HCL 相关错误的子集，旧版本的 Packer 最多显示同一消息五次。
得益于社区贡献，从 Packer 1.12 开始，我们不再遇到这种情况。
