# 升级到 v1.11

本主题描述 Packer v1.11 的升级注意事项。有关 v1.11 中更改的详细信息，请参阅 [v1.11 发布说明](/docs/release-notes/v1_11)。

## 概述

你可以使用安装 Packer 时使用的包管理器的升级命令，或下载并替换现有二进制文件来升级 Packer。有关说明，请参阅[安装 Packer](https://developer.hashicorp.com/packer/install)。

## 从 1.10 升级

由于 v1.10 和 v1.11 之间的更改，请采取以下操作。

### 检查模板

Packer v1.11 支持现有的 v1.10 模板。无需采取任何操作。

### 检查插件管理流程

由于我们对 Packer 管理插件的方式进行了以下更改，你应该检查你的插件管理流程并相应地进行更改：

* 不再支持单组件插件。将你的依赖项更新为多组件插件。例如，将 `packer-builder-hashicups-coffee` 更新为 `packer-plugin-hashicups`。

* Packer 要求所有插件都安装在插件目录中。插件必须遵循与预期来源匹配的层次结构。插件必须遵循 `packer-plugin-<name>` 命名约定。插件必须附带 `SHA256SUM` 文件。如果你在 Packer 插件目录之外管理插件安装，请修改你的安装流程以满足这些要求。有关更多信息，请参阅[安装插件](/docs/plugins/install)。

* Packer 要求从 Packer HCL2 模板安装的插件使用语义版本控制。有关更多信息，请参阅 Packer 插件安装文档中的[要求](/docs/plugins/install#requiremets)。

* 你可以使用 `packer plugins install --path` 命令在构建中使用插件的 `-dev` 预发布版本。请参阅[使用开发中的插件](/docs/plugins/install#use-a-plugin-under-development)。

* 你可以使用 `packer plugins install --path` 命令从非 Github 主机安装插件。此命令将插件安装到 Packer 插件目录中，并创建与提供的来源匹配的文件层次结构。因此，Packer 能够发现在 `required_plugins` 块中指定的非 Github 来源。这使你可以根据需要对这些插件添加版本约束。
  虽然你可以出于验证目的将非 GitHub 来源添加到 `required_plugins`，但远程安装仍然仅限于 Github 来源的插件。有关更多信息，请参阅 `required_plugins` 参考文档中的[定义插件来源](/docs/templates/hcl_templates/blocks/packer#define-plugin-source)。

## 故障排除

本节提供有关升级后可能遇到的潜在问题的指导。

### 缺少插件错误

升级后 Packer 可能会报告缺少一个或多个插件。
如果你使用了以下不再支持的插件安装方法之一，可能会发生这种情况：

* 将插件安装到调用 Packer 的目录中。
* 将插件安装在 Packer 二进制文件旁边。
* 将插件安装在 `PACKER_PLUGIN_PATH` 目录的根目录下。

对于任何缺少的组件，你可能需要按照[安装插件](/docs/plugins/install)中的说明重新安装其各自的插件。

### 使用 `required_plugins` 消息

Packer 可能会打印一条消息，指示你在模板的 `required_plugins` 块中指定插件，并使用 `packer init` 命令安装它们。
这是管理插件的首选方式，但不是必需的。你仍然可以使用 `packer plugins install` 命令手动安装插件。请参阅[安装插件](/docs/plugins/install)。

### 阻止远程访问插件

如果由于任何原因（如防火墙配置或 GitHub 阻止访问）无法远程安装插件，你可以使用本地安装方法。请参阅[安装插件](/docs/plugins/install)。

### 从旧版 JSON 模板安装插件

`required_plugins` 块仅在 HCL 模板中可用。旧版 JSON 用户必须使用 `packer plugins install`。

## 在命名空间目录之外安装插件

Packer 不再支持在单个根目录下安装名为 `packer-plugin-<name>` 的插件。
你仍然可以使用 Packer CLI 命令安装插件，并通过设置 `PACKER_PLUGIN_PATH` 环境变量使其指向自定义目录来自定义哪个根目录管理这些插件。
设置后，Packer 会自动在该目录下创建与插件来源匹配的子目录。
